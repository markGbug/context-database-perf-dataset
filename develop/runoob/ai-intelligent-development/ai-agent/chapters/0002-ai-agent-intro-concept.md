## 本章内容

AI Agent（人工智能智能体）是一种能够根据目标自主决定部分操作步骤，并调用工具完成任务的 AI 系统。

与主要用于问答、文本生成的 AI 助手不同，Agent 不只是提供答案，还可以在获得相应权限后执行操作。例如，读取文件、查询数据库、运行代码、调用 API，或者操作其他软件。

假设你有一份销售数据，需要整理并生成图表。

使用普通的 AI 聊天工具，你可能需要先上传数据，再分别提出分析和绘图要求；而具备文件读取和代码执行能力的 Agent，可以根据任务要求，自动读取数据、分析结果、生成图表，并保存到指定位置。

简单来说，AI Agent 的重点不是能回答多少问题，而是能够调用工具，把任务一步步完成。

一个典型的 LLM Agent 通常涉及以下几个部分：

- 大语言模型（LLM）：理解任务、分析信息，决定下一步操作。
- 规划（Planning）：将复杂任务拆分成多个步骤，并根据执行情况调整计划。
- 工具调用（Tool Use）：通过 API、代码执行环境或软件接口完成具体操作。
- 记忆与状态（Memory / State）：保存执行过程中的信息，必要时读取历史记录或外部知识。

这些模块并不是所有 Agent 都必须具备的独立组件。简单的 Agent 可能只需要模型和工具，复杂系统则可能加入任务规划、长期记忆和多 Agent 协作等能力。


## AI Agent 与传统 AI 模型的区别

大语言模型（LLM）主要负责处理输入并生成输出，而 Agent 是围绕模型构建的任务执行系统。

两者并不是相互替代的关系。大语言模型通常是 Agent 的核心组件之一，Agent 则在模型基础上增加工具调用、执行控制和状态管理等能力。

例如，用户提出"分析最近三个月的网站访问数据，并生成一份报告"。

普通 LLM 应用通常需要用户提供数据，再根据数据进行分析；而具备相关权限的 Agent，可以调用统计接口获取数据、使用 Python 计算指标、生成图表，最后整理成报告。

需要注意，现代 AI 聊天应用也可能具备工具调用和自动执行能力，因此普通 AI 助手与 Agent 之间并没有绝对的技术界限。


## AI Agent 如何工作？

Agent 的核心工作方式是根据任务目标不断执行操作，并利用执行结果决定下一步做什么。

一种常见的实现模式是 ReAct（Reasoning and Acting），即将推理与行动结合起来。

其基本执行流程如下：

- 接收任务：用户提出需要完成的目标。
- 分析任务：模型判断需要哪些数据、工具和执行步骤。
- 调用工具：执行搜索、读取文件、运行代码等操作。
- 获取结果：读取工具返回的信息，判断操作是否成功。
- 继续执行：根据结果调整后续步骤，直到完成任务或需要人工介入。

例如，让 Agent 完成"读取 Excel 文件，统计各地区销售额并生成柱状图"：

- 读取指定的 Excel 文件。
- 识别表格中的地区和销售额字段。
- 使用 Python 汇总各地区的销售数据。
- 调用绘图库生成柱状图。
- 保存图表，并返回文件位置。

如果读取文件失败，Agent 可以根据错误信息尝试修正文件路径，或者向用户询问文件位置。

这种根据执行结果持续调整操作的方式，是 Agent 区别于简单固定流程自动化的重要特点之一。

不过，ReAct 并不是 Agent 唯一的实现模式。实际开发中，也可以采用预先规划、工作流编排或者模型直接调用工具等方式。


## AI Agent 的核心组成

一个 Agent 系统通常由模型、工具和执行控制逻辑组成。根据任务复杂程度，还可以增加记忆、规划以及多个 Agent 之间的协作能力。


### 1、任务规划

任务规划负责将用户提出的目标转化为具体操作。

例如，用户要求"分析公司上季度的销售情况"，Agent 可以将任务拆分为：

- 读取上季度的销售数据。
- 按月份、产品或地区汇总。
- 计算销售额及增长率。
- 生成图表和分析报告。

对于简单任务，Agent 不一定需要提前生成完整计划，也可以根据工具返回的结果逐步决定下一步操作。


### 2、记忆与状态管理

Agent 在执行任务时，需要记录必要的信息，例如用户要求、已完成的步骤和工具返回结果。

常见的记忆方式包括：

- 短期记忆：保存当前对话、任务状态以及中间结果。
- 长期记忆：通过数据库、文件或向量数据库保存需要长期使用的信息。

例如，Agent 可以在任务过程中记录已经处理过的文件，避免重复执行；也可以在获得授权后保存用户偏好，供后续任务参考。

长期记忆并不是所有 Agent 的必需功能。对于一次性的文件转换、数据查询等任务，保存当前执行状态通常就足够了。

## AI Agent 的主要特点

不同的 Agent 在能力上存在差异，但通常具有以下几个特点：

- 目标导向：根据用户提出的目标组织和执行操作，而不只是生成一段回答。
- 自主执行：可以在允许的范围内自行选择工具及操作顺序，减少人工逐步干预。
- 环境反馈：根据工具返回的结果调整后续操作，例如在请求失败后尝试其他方案。
- 持续交互：在任务执行过程中可以与用户交流，确认需求或请求必要权限。
- 状态管理：记录已完成的步骤和中间结果，便于继续执行或恢复任务。

并不是所有 Agent 都必须具备学习能力，也不意味着 Agent 会在使用过程中自动更新模型参数。

大多数应用主要通过上下文、外部知识库和记忆机制改善后续执行效果，而非直接重新训练底层模型。


## AI Agent 的发展历程

Agent 并不是大语言模型出现之后才提出的概念。人工智能领域早在几十年前就已经开始研究能够感知环境、作出决策并采取行动的智能体。

近年来，随着大语言模型的出现，Agent 的自然语言理解、任务规划和工具调用能力得到了明显提升。

从早期的规则系统，到今天基于大语言模型的 Agent，智能体技术逐渐从特定任务的自动化，发展到能够理解自然语言并调用多种工具完成任务的系统。


## 多 Agent 协作

除了使用一个 Agent 完成整个任务，还可以让多个 Agent 分别负责不同工作，这种方式称为多 Agent（Multi-Agent）协作。

例如，在软件开发项目中，可以安排不同的 Agent 承担不同职责：

- 设计 Agent：分析需求，设计系统架构与接口。
- 编码 Agent：根据设计编写代码。
- 测试 Agent：运行测试并检查代码问题。
- 协调 Agent：分配任务、跟踪进度并整理结果。

一种常见的协作流程是：

```text
用户提出需求
      ↓
协调 Agent
      ↓
设计 Agent
      ↓
编码 Agent
      ↓
测试 Agent
      ↓
汇总结果并交付
```

实际系统也可以让多个 Agent 并行工作。例如，前端 Agent 和后端 Agent 分别开发不同模块，最后由测试 Agent 进行集成检查。

多 Agent 并不一定比单 Agent 更好。多个 Agent 需要交换上下文、协调任务和处理冲突，可能增加运行成本与系统复杂度。

对于简单任务，通常使用一个 Agent 更直接；只有当任务可以明确拆分，或者需要不同专业能力时，多 Agent 协作才更有价值。


## AI Agent 的主要类型与应用场景

AI Agent 可以按照任务范围、交互方式和执行能力进行分类。不同分类之间可能存在交叉。


### 常见应用

1、软件开发

AI 编程 Agent 可以读取代码仓库、修改项目文件、运行测试并协助排查错误。例如 Claude Code、Codex 等工具，已经将 Agent 的能力应用到实际开发流程中。

2、办公自动化

Agent 可以读取电子表格、整理文件、生成文档，并通过授权的工具与邮件、日程和其他办公系统交互。

3、数据分析

通过连接数据库和 Python 执行环境，Agent 可以完成数据清洗、统计计算、可视化以及报告生成。

4、信息检索与研究

Agent 可以围绕一个问题进行多轮搜索、阅读资料、整理信息，并生成包含来源的研究结果。

5、企业业务流程

企业可以将 Agent 接入现有业务系统，协助处理工单、整理客户资料、生成报表等重复性工作。

这些应用能够实现多大程度的自动化，取决于具体工具、权限、执行环境和人工审批流程。


## AI Agent 的局限性

虽然 Agent 能够自动执行多个操作步骤，但并不意味着它可以可靠地完成任何任务。

实际使用中，仍然需要注意以下问题：

- 结果可能出错：模型可能误解需求、生成错误信息，或者调用不合适的工具。
- 操作可能失败：网络中断、接口变更、文件格式不兼容等情况，都可能导致任务失败。
- 执行成本：复杂任务可能需要多次模型调用和工具操作，增加时间与费用。
- 权限与安全：如果工具权限过大，错误操作可能修改文件、泄露数据或影响业务系统。
- 缺少稳定性：同一个任务在不同环境或不同执行过程中，可能得到不同结果。

因此，在实际项目中，建议根据任务风险设置明确的执行边界。

例如，允许 Agent 自动查询数据、生成报告，但对于删除文件、修改数据库、支付费用以及向外部发送信息等操作，应根据风险要求增加人工确认。

开发 Agent 系统时，还需要考虑执行日志、超时限制、错误重试、权限控制和结果验证等问题。


### AI Agent 的发展方向

随着模型和工具能力的发展，AI Agent 正在向更复杂的任务执行场景扩展。

一些值得关注的方向包括：

- 软件与桌面操作：从通过 API 调用工具，扩展到理解和操作图形界面。
- 多 Agent 协作：通过任务分工处理较复杂的软件开发和业务流程。
- 本地化运行：在个人电脑或企业内部环境中执行任务，减少部分数据外传需求。
- 专业领域应用：结合行业知识、专用工具和审批流程，处理更具体的工作任务。

AI Agent 的价值不在于完全取代人工操作，而在于减少重复工作，让用户把更多精力放在需求判断、结果审核和重要决策上。

对于开发者而言，理解 Agent 的基本原理只是第一步。真正需要掌握的是如何让模型安全地调用工具、管理任务状态，并验证每一步操作的结果。
