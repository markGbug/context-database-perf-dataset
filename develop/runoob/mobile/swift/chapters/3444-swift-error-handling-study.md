## 本章内容

程序运行中总会遇到预期之外的情况：文件不存在、网络断开、用户输入格式不对。

Swift 用一套显式的错误处理机制来描述这些可恢复的失败，把「这个操作可能失败」直接写进函数签名，让编译器帮你盯住每一个调用点。

本文覆盖 Error 协议、throw / throws / try / do-catch、try? / try!、defer、rethrows 与 Result，最后说明什么时候该用错误、什么时候用可选类型就够了。


## 为什么需要错误处理

没有错误处理机制时，函数通常只能靠特殊返回值来报告失败，例如返回 -1、空字符串或者 nil。

这种做法的问题在于：调用方很容易忘记检查，而且「为什么失败」的信息在传递过程中丢掉了。

Swift 的做法是把失败写进函数签名，调用方必须用 try 明确表态，编译器负责检查你是否处理了这个错误。


## Error 协议与自定义错误类型

Swift 中的错误类型必须遵循 Error 协议。

这个协议没有任何必须实现的要求，它只是一个标记，表示这个类型可以当作错误抛出。

最常用的定义方式是用枚举，因为枚举可以把所有可能的失败原因清楚列出来，再用 switch 或 catch 逐一处理。

## throw 与 throws

throw 用来抛出一个错误，throws 用来声明「这个函数可能抛出错误」，两者是一对。

只有被标记为 throws 的函数、以及 do 块内部，才能写 throw。

一旦执行到 throw，当前函数会立刻中断，后面的代码不会执行，控制权交回调用方。


## 实例

运行结果：

```text
步骤 1 开始
步骤 1 完成
OK
步骤 2 开始
中断：notFound("步骤 2")
步骤 3 开始
步骤 3 完成
OK
```

从输出可以看到，第 2 步在 throw 处直接中断，后面的「步骤 2 完成」和返回值都没有出现。

但循环本身没有被打断，第 3 步照常执行，因为错误已经被 do-catch 接住了。


## try 与 do-catch

调用一个 throws 函数时必须写 try，这是在语法上提醒你「这里可能失败」。

最常见的处理方式是 do-catch：把可能出错的代码放进 do 块，错误在 catch 块里统一处理。

do 块中任意一行抛出错误，都会跳到 catch，do 块中剩下的语句不再执行。


### catch 的匹配顺序

catch 从上到下依次匹配，第一个匹配上的分支被执行，后面的分支不再尝试。

因此要把具体错误写在前面，把笼统的 catch 放在最后。

Swift 的错误不是「异常」。它不会自动向上冒泡到任意位置，只能沿着函数调用链逐层传播，或者被某个 do-catch 就地处理。


## try? 与 try!

有些场合并不需要区分失败原因，只想知道「成功还是失败」，这时可以用 try? 把结果变成可选类型。

try? 成功时返回包装好的可选值，失败时返回 nil，原来的错误信息被丢弃。

try! 则是断言「这次调用一定不会失败」，一旦真的失败，程序会直接崩溃。


## 实例

运行结果：

```text
42
true
100
```

不要把 try! 当作「懒得写 do-catch」的快捷方式。它把编译期的检查换成了运行期的崩溃风险，正式代码里应当谨慎使用。


## defer 清理动作

defer 用来声明一段「离开当前作用域前一定执行」的代码，无论函数是正常返回还是抛出错误。

它适合用来配对地做清理：打开文件后关闭、加锁后解锁、开始任务后打印日志。


## 实例

运行结果：

```text
1. 打开文件：runoob.txt
2. 读取内容
3. 关闭文件：runoob.txt
RUNOOB 文档内容
```

同一个作用域里可以有多个 defer，它们按声明的逆序执行，也就是后声明的先执行。


## 实例

运行结果：

```text
开始
C
B
A
```

defer 是在离开作用域时执行，不是「函数结束时」执行。写在 if 或循环体里的 defer，会在该块结束时触发。


## 错误传播与 rethrows

函数自己不处理错误时，可以在签名里声明 throws，把错误原样交给调用方，这叫错误传播。

传播链上的每一层都要写 try，直到某一层用 do-catch 处理掉为止。


## 实例

运行结果：

```text
用户：runoob
其他错误：notFound(2)
编号无效：0
```

rethrows 是给「接受函数参数」的高阶函数用的。

它表示：这个函数本身不产生错误，只有当传入的闭包抛错时，它才把错误继续传出去。


## 实例

运行结果：

```text
[2, 4, 6]
出错：notANumber("2")
```

rethrows 的好处是保留调用方的灵活性：传入不抛错的闭包时，调用点不用写 try，也就不会被迫进入 do-catch。

用 rethrows 的函数，其闭包参数必须标为 throws，而且函数体内不能自己写 throw。


## Result 类型

Result 是一个枚举，把「成功」和「失败」两种结果装进同一个值里（SE-0235，Swift 5 引入）。

它适合用在错误需要被保存、传递、延迟处理的场合，例如异步回调、或者把错误存进数组。


## 实例

运行结果：

```text
分数：88
get 抛出：notANumber("runoob")
```

Result 还提供了一些常用方法，方便在不展开 switch 的情况下变换结果。

在 async / await 普及之后，异步场景更推荐直接用 async throws 函数，而不是回调里传 Result。但 Result 在需要「把结果存起来」的场合依然不可替代。


## 与可选类型的选择

可选类型和错误都能表示「没拿到值」，但表达的信息量不同。

官方文档给出的判断依据是：失败原因对调用方有没有意义。

如果只是「查不到」「没有下一个」这类单一含义，可选类型更轻量；如果失败可能有多种原因，而且调用方需要据此做不同处理，就用 throws。


## 实例

运行结果：

```text
RUNOOB 管理员
查无此人
登录成功，欢迎 runoob
```

还有一种情况是「失败属于程序 bug，不可恢复」，例如数组越界、强制解包 nil。

这类问题 Swift 用运行时陷阱（trap）处理，直接终止程序，不进入错误处理流程。

不要用错误处理来掩盖逻辑错误。如果某个条件不满足就说明程序写错了，用 precondition 或 fatalError 更诚实。
