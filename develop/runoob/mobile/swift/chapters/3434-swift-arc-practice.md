## 本章内容

自动引用计数（Automatic Reference Counting，简称 ARC）是 Swift 管理类实例内存的方式。

它自动跟踪每个实例被多少个引用持有，一旦没人再引用，就释放这块内存。

ARC 处理不了的是「互相引用」和「闭包捕获自己」这两种情况，需要配合 weak 与 unowned 手动打破。


## ARC 的工作原理

每创建一个类实例，ARC 就为它记一个引用计数。

每多一个强引用，计数加一；每少一个强引用，计数减一；计数归零时，实例被销毁并调用 deinit。

这些加减由编译器自动插入，不需要手写 retain 或 release。


注意：ARC 只作用于类实例。结构体和枚举是值类型，它们的生命周期由作用域和复制决定，不存在引用计数。


## 强引用与引用计数

默认的引用都是强引用，只要还有一个强引用存在，实例就不会被释放。

把变量置为 nil 只是减少一个引用，计数没到零，实例就还活着。


## 实例

执行以上代码输出：

```text
RUNOOB 被创建
还剩 ref3 持有实例
RUNOOB 被销毁
全部释放
```

deinit 只能由 ARC 调用，不能手动调用，也不能在里面抛错。


## 循环强引用

如果两个实例互相持有对方的强引用，它们的引用计数永远不会归零。

这就是循环强引用（retain cycle），也是 ARC 最常见的内存泄漏来源。


## 实例

执行以上代码输出：

```text
Runoob 被创建
公寓 A-101 被创建
两个对象互相持有，引用计数都还是 1，deinit 不会执行
```

注意输出里没有任何「被销毁」，说明两个实例都还留在内存里。

打破循环的办法是：把其中一端的引用改成 weak 或 unowned。


## 弱引用 weak

弱引用不会增加引用计数，目标被释放时它自动变成 nil。

因为可能变成 nil，弱引用必须是 var 声明的可选类型。

```text
结束
```

弱引用适合表达「不是拥有关系」：代理对象、父节点回指子节点、缓存条目等。


## 无主引用 unowned

无主引用同样不增加引用计数，但它假设目标永远比引用者活得久。

因此它可以是 let，也可以是非可选类型；代价是目标被释放后再访问它，程序会直接崩溃。

经典场景是「信用卡一定属于某位客户，且客户一定比卡活得久」。

```text
客户 Runoob 被销毁
信用卡 6222-0000 被销毁
结束
```

## 闭包引起的循环引用

闭包会捕获它用到的外部变量，包括 self。

如果实例又持有这个闭包，就构成了「实例 → 闭包 → 实例」的循环。

## 捕获列表与 guard let self

解决办法是在闭包开头写捕获列表 [weak self]，让闭包不持有实例。

由于 self 变成了可选类型，访问前要先解包，标准写法就是 guard let self else { return }。


## 实例

执行以上代码输出：

```text
站点：www.runoob.com
Reporter 被销毁
对象已释放
```

guard let self else { return } 的作用是把「self 已释放」这种情况提前处理掉，避免后续代码访问一个空对象。

在返回 Void 的闭包里直接写 return，在返回值的闭包里则返回一个兜底值。

只在闭包会被存储、逃逸出当前作用域时才需要捕获列表；同步执行完就丢弃的闭包不会造成循环。


## 常见问题

下面几个问题在排查内存泄漏时最常遇到。


### 什么时候该写捕获列表

当闭包被实例持有、或者闭包会逃逸并长期存活，而闭包里又用到了 self 时，就加上捕获列表。

反过来，传给 map、sorted 这类同步执行的闭包，通常不需要。


### 为什么加了 weak 之后还要 guard let self

因为 weak 把 self 变成了可选类型，直接用会有编译错误。

用 guard let self else { return } 一次性解包，后面就能像普通实例一样访问。


### weak 和 unowned 到底怎么选

目标可能先释放、或者两者的生命周期没有明确关系时，用 weak。

只有当你能明确保证目标一定比引用者活得久，并且不想处理可选值时，才用 unowned。


### 循环引用能自动被发现吗

编译器不能，ARC 也不能。它只负责引用计数，不分析对象之间的关系。

排查时可以用 Xcode 的 Memory Graph 或 Instruments 的 Leaks 模板，观察那些本该销毁却没有 deinit 的对象。
