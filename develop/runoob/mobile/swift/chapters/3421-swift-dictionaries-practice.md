## 本章内容

字典（Dictionary）用来按键值对存放元素，通过键快速找到对应的值，查找过程与元素数量无关。

它和数组一样是值类型，赋值和传参时保持独立；但它不保证顺序，这一点和数组正好相反。

本篇讲字典的创建、增删改、default 下标、遍历、mapValues 与 merging，以及键的 Hashable 要求。

按位置存放元素请见《Swift 数组》。

## 遍历字典

字典是无序集合，遍历顺序不保证，也不等于插入顺序，更不能跨版本、跨平台地假设它稳定。

需要稳定输出时，先对键排序再遍历。

```text

[5, 10, 11]
```

直接写 for (key, value) in ages 得到的顺序是不确定的，上面第一段代码只累加求和，不依赖顺序，所以输出稳定。

sorted(by:) 把字典转成按指定规则排列的 (key, value) 数组，再遍历就固定了。

keys 与 values 返回的是视图，本身也没有顺序保证，通常要再套一层 sorted() 使用。

注意：不要依赖观察到的「插入顺序」。字典内部用哈希表存储，元素的排列取决于哈希值和当前容量，扩容后还可能变化。

## 键的要求

键必须遵循 Hashable 协议，因为字典要靠哈希值定位元素。

字符串、整数、浮点数、布尔、枚举等常见类型都满足这个要求，自定义结构体也能自动合成实现。

结构体的成员都是 Hashable 时，编译器会自动合成 Hashable 与 Equatable 的实现，不需要手写。

注意：类的实例默认按「引用」比较，不会自动按属性合成哈希。如果要把类当作键，需要自己实现 Hashable 与 ==。


## 常见问题

下面是字典使用中最常见的几个问题。


### 为什么字典遍历顺序每次都不一样

字典内部用哈希表存储，元素的排列取决于哈希值和容量，Swift 不承诺任何顺序。

需要顺序时请显式排序，例如 ages.sorted(by: { $0.key < $1.key })，不要依赖观察到的「插入顺序」。


### 字典是值类型还是引用类型

是值类型。赋值给另一个变量后修改其中一个，另一个不受影响，和数组一样由写时复制优化。

这与 Objective-C 中共享同一个对象的 NSDictionary 完全不同。


### 计数场景怎么写得简洁

用 default 下标，counts[word, default: 0] += 1 一行就能完成「不存在则初始化，存在则累加」。

换成普通下标要先写 if let 判断，再赋值回去，代码会长不少。


### 键必须是什么类型

必须遵循 Hashable，绝大多数标准库类型都满足。

自定义结构体或枚举作为键时，让它们遵循 Hashable 即可，Swift 能自动合成实现。
