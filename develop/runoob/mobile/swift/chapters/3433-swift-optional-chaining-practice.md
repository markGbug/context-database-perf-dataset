## 本章内容

可选链（Optional Chaining）是一种在值可能为 nil 时安全访问其属性、方法或下标的写法。

它把「先判断是不是 nil，再取值」压缩成一个问号：链上任意一环为 nil，整个表达式就返回 nil，程序不会崩溃。

### 可选链的结果总是可选值

可选链不会改变原始类型，只是在外面再包一层可选。

注意：即使 numberOfRooms 本身是 Int（非可选），通过可选链访问后得到的也是 Int?。所以要取值时必须用 if let 或 ?? 把它解出来。

## 通过可选链调用方法

把问号放在方法名前面，方法就变成「存在才调用」。

调用成功时返回值被包装成 Void?，因此可以用 != nil 判断方法到底有没有执行。


## 实例

执行以上代码输出：

```text

```

如果方法本身有返回值，比如 String，通过可选链调用后同样得到 String?。


## 通过可选链访问下标

下标的问号写在方括号前面：residence?[0]。

注意 ?[0] 里的问号作用在 residence 上，而不是作用在数组元素上。

## 多层可选链

一层可选链后面可以继续接可选链，形成多层链。

链上任何一环为 nil，整个表达式就短路返回 nil，后面的成员不会被访问。

执行以上代码输出：

```text

```


## 可选链与空合运算符配合

可选链返回的永远是可选值，最常用的搭档就是空合运算符 ??。

?? 会在左侧为 nil 时给出一个默认值，让结果重新变成非可选类型。


## 实例

执行以上代码输出：


需要区分「值为 nil」和「值为 0」时，就不能用 ?? 直接把结果压成非可选，而要改用 if let 判断。


## 可选链赋值

可选链也可以放在等号左边，用来给属性赋值。

链断了赋值就不执行，而且等号右边的表达式也不会被求值，不会产生多余的副作用。

执行以上代码输出：

```text

```

利用这一点，可以给「对象存在时才需要做的准备工作」加上可选链，省掉一层 if 判断。


## 常见问题

下面几个问题在初学可选链时最常遇到。


### 为什么 Int 变成了 Int?

因为可选链的结果必须能表示「链断了」这种情况，所以无论成员原本是不是可选，结果一律再包一层可选。

取值时用 if let、guard let 或 ?? 解包即可。


### 可选链和强制解包 ! 怎么选

可选链在 nil 时安静返回 nil，强制解包在 nil 时直接崩溃。

只有当你百分百确定值不为 nil，或者已经用 if let 判断过，才考虑用 !。


### 方法调用的结果怎么判断

返回 Void 的方法通过可选链调用后得到 Void?，可以写成 person.residence?.printNumberOfRooms() != nil。

如果只关心调用有没有发生，这种写法比先判断 residence != nil 更紧凑。


### 可选链能不能连续用在不同类型的可选值上

可以。每一环只关心「当前这个可选值是不是 nil」，类型不同不影响链接。

比如 person.residence?.address?.buildingIdentifier() 里，三个环节分别是 Residence?、Address? 和返回值 String?。


### 可选链能替代空值检查吗

不能完全替代。可选链只处理「链上某一环是 nil」，不会检查数组越界、类型转换失败等其它运行时错误。

需要在这些场景下给出不同的分支逻辑时，仍然要用 if let、guard let 或 switch 显式判断。
